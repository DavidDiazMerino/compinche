## Continuous live learning (Compinche additions)

The Spanish **Compinche · aprender en directo** panel starts one explicitly consented live session. Start the SDK preview first. This client sends JPEGs copied with PixelCopy from the actual SDK-decoded Surface (640px longest edge, sample every 750 ms, rolling four-frame window, conflated sending every 1500 ms), not images fabricated from compressed HEVC buffers or the selected mock file. JPEGs and phone microphone samples share a monotonic session clock; the last rendered SDK PTS is separate, approximate metadata. Mock replay cannot establish an exact original-file offset.

Microphone audio is PCM16 mono 24 kHz captured with AudioRecord, using AEC/noise suppression where the phone supplies them. A local backend WebSocket forwards real-time chunks; API credentials stay on the server. It is negotiated before microphone capture. Each speech onset freezes its utterance ID, declared speaker, pending question ID and Unix speech-start time. WAV fallback stores its actual sample duration and separate pre-roll capture time. Transport failure discards an ambiguous partly streamed turn until a real silence; that turn is never submitted again as a WAV. WAV fallback is bounded to 30 seconds per utterance, four queued turns, and retries the same ID. Successful HTTP 202 acceptance precedes clearing the human-speaking fence. Streaming transcription still depends on the configured upstream provider.

Approved pending questions play through the local Piper WAV route when available, with Android Spanish TTS fallback. Playback acknowledges the question only on actual audio start. Microphone input is silenced to the real-time service and excluded from local turns during synthesis and a 650 ms tail; **Interrumpir** explicitly stops voice. This avoids self-transcription but does not claim automatic acoustic barge-in, speaker diarization, or hardware echo performance. Speaker name and role are selected by the user; ASR is not human confirmation.

If no SDK recording is already active, starting learning also records the continuous actual SDK video. Stopping learning finalizes the owned original, copies it into private app files before upload, and associates it with the linked learner session through a stable content receipt. Failed uploads retain the local file and can be retried with **Reintentar copias locales**. The SDK original is video-only when this path owns capture; microphone utterances are preserved separately as audio evidence. An already-running manual recording is not automatically owned or finalized by this flow. Files above 150 MiB remain local because the evidence upload has that limit.

The live bridge is foreground-only: Activity ON_STOP, stream termination and screen disposal stop microphone/analysis and finalize an owned original. The original official SDK preview/decoder/recorder is retained. The capture buttons are disabled while live learning owns recording. Forced process death cannot guarantee finalization or a server stop request. Do not describe this build as validated background glasses capture.

Build validation runs assembleDebug, assembleDebugAndroidTest and lintDebug through `../build-container.sh`. `LiveAudioPacketTest` compiles an Android MediaExtractor check of the emitted mono 24 kHz WAV. Neither this test nor SDK/hardware, microphone, PixelCopy, speech playback or archive runtime has been executed without a connected Android 12+ phone. Install and execute the instrumentation package before claiming device validation.
